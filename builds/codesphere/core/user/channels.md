# How drafts read on each channel

_A starting set, to make your own. Each section is how a draft should read on that channel: length, format, tone. Your own voice ([voice.md](voice.md)) comes first; this is the channel's on top. Change anything here, or say "drafts for chat should be shorter" and it's changed with you._

## Pull request description

- Title under 70 characters, saying what changes.
- A summary as a few bullets: what, and why.
- How it was tested, as a checklist.
- Before and after screenshots for anything people can see.
- Nothing about the sphere.

## Review comment

- Specific, and anchored to the line.
- Direct, not adversarial.
- Ask when unsure, rather than assert.

## Team chat

- Short. The point in the first line.
- The chat tool's own markup; code in code blocks.

## Issue tracker comment

- Plain text in the tracker's markup.
- Refer to issues by their key, never a bare number.

## Email

- A subject line, drafted too.
- The greeting matches how well you know them.

## Meeting agenda item

- A numbered line: the topic, and a link to what it's about.
