# How fresh a view is

**Applies to:** rendering any projection, *"refresh"*, a ground that changed something a projection reads, and anyone asking *"is this current?"*

## Four kinds, declared up front

| Kind | Promise | Brought up to date | Example |
|---|---|---|---|
| **live** | Always current | It reads its sources when it's opened, and again when it regains focus | What's in motion, read from the work index |
| **refreshed** | Current as of its last render | A render step, at ground or on `refresh <name>` | A view built from exported account data |
| **snapshot** | Faithful to a moment | Never. It's made once | A year in review; a walkthrough of one change |
| **external** | Whatever its app declares | By the app: `on-ground`, `on-open` or `manual` | An app outside the sphere that reads it |

- **The kind is chosen when the projection is made, and it doesn't drift.** Changing it is a change to the definition, made on purpose.
- **Mixing kinds is a bug both ways.** A live view that went stale lies to the reader. A snapshot that gets refreshed loses the moment it existed to keep. So `refresh` refuses a snapshot: a new moment is a new snapshot.
- **An external app must declare how it stays current.** *Why:* an outside app with no declared refresh is exactly how a view ends up silently stale. Without one, it's shown as stale after a day.

## Live means it reads its sources

**A live view holds no copy of its data.** It reads its source files when it's opened, with no build step. *Why:* a page with its data baked in silently stops showing new entries the day the copy and the source part ways. Reading the source on open removes that whole class of drift.

**A live view relies on the shape of what it reads.** That shape is the tree's declared frontmatter in `core/shapes`, not something the page discovers. So when a shape changes, the [structure check](../readable-substrate/structure-check.md) and the views that read it change in the same step.

## Refreshed means a render step

- **At ground,** a refreshed view is rendered again if any of its `sources` changed in that ground. That's computed from what the ground changed, never tracked separately.
- **On request:** `refresh <name>`, or `refresh all`, which skips live views and snapshots because they have nothing to refresh.
- **Stale is computed, not stored.** A refreshed view is stale when one of its sources changed after it was rendered, or when it's past its `freshness` window. Git already knows both. Fire `projection-stale` when one is found outside a ground.

## Snapshots are made once

A snapshot is built with the one-shot template: read across the sphere, compose it, stamp where it came from, write it once, freeze it. See [projection-templates](projection-templates.md#the-one-shot-template). Its sources moving on later is expected; nothing re-renders it.

## The render takes no judgment

**Live and refreshed renders are deterministic:** the same sources give the same page, every time. No AI judgment runs in the render. The intelligence was spent once, choosing what to show and designing how. *Why:* that's what makes a live view trustworthy. Nothing in it was guessed this time.

**A machine-readable copy of a source** (a feed a page reads more easily than markdown) is written by the same step that writes the source, or generated by tooling. A copy kept up separately is a second truth waiting to drift.

## What a view shows: what's been grounded

**The artifact renders from the sphere's latest commit,** never from a focus's unsaved work. A human opens their page without caring which focus is in the foreground, and what they see is what's been saved.

- **A focus can preview** its unsaved changes by rendering into `surface/projections/_scratch/`, marked plainly as a preview. The real artifact changes only when the focus grounds.
- **A change to a definition rides the focus** like any authored file. It's previewed in scratch and reaches the real artifact at ground.

## Every page says what it is

**Each artifact carries its own provenance,** inside the page and not only in the registry:

- **what it was built from** (its sources) and **when it was rendered;**
- **its kind,** so a reader can tell live from snapshot at a glance;
- **a staleness notice,** shown where the reader is looking, when a refreshed view is past its freshness.

*Why on the page:* a projection gets copied, shared and screenshotted. Wherever it ends up, it can still say where it came from and how old it is.

**Derived view data** (a rollup, a sorted list, a chart series) sits beside the artifact and is never committed. It's a cache, rebuilt from the sources and the definition at any time.

## When / do

| When | Do |
|---|---|
| A projection is made | Render it according to its kind, with provenance stamped in. Snapshots go through the one-shot template |
| A ground changed a refreshed view's sources | Render it again, as part of the ground |
| *"Refresh X"* | Render X from its sources. Fire `refresh-requested`. Refuse if X is a snapshot, and offer a new one |
| *"Refresh all"* | Render every refreshed view; skip live views and snapshots |
| A refreshed view is found stale outside a ground | Show it as stale on the page; fire `projection-stale`; offer to refresh |
| An external app has no declared refresh | Treat it as stale after a day; ask the human how it should stay current |
| A focus wants to see its changes in a view | Render a preview into `_scratch/`, marked as a preview |
| *"Is this current?"* | Answer from the page's provenance and the sources' last change |
| A source's shape changes | Change the views that read it, and `core/shapes`, in the same step |
