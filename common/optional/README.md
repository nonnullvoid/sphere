# Optional frames

_Frames that solve problems a sphere only has once it's large or busy. No build ships them; a sphere adopts one when it needs it._

A fresh sphere is small, and the plainest way of doing things is the fastest. After months of daily use, some parts grow enough that a heavier technique starts to pay for itself. The frames here are those techniques, written down and ready, so a sphere that hits the problem doesn't have to invent the answer.

- **Each one belongs to a common lens,** and is written for where it will live: `frames/<lens>/<frame>.md` here becomes `core/protocol/frames/<lens>/<frame>.md` in a sphere. Its links are written for that place, so they resolve once it's adopted, not here.
- **Each one says when it's worth it,** and what to measure first. Adopt one because something measured slow, never in advance.
- **Adopting one is a sphere change,** made in sphere authoring with the human's yes. The frame lists the steps: copy it in, add it to its lens's `frames:`, add any script it needs, rebuild the manifest.
